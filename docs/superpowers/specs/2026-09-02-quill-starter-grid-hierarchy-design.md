# Quill 任务入口层级设计

**状态：设计已确认，待实现**  
**日期：2026-09-02**

## 目标

重做 `/quill` 首页的“今天，要推进什么？”任务入口区。解决四张等大、等重、留白过多的白卡导致页面像组件库陈列的问题，同时保持快捷任务的 prompt 预填与研究模式切换行为。

## 已确认方案：杂志式任务入口

在桌面宽度下，将入口区改为 5:3 的两列构图：

- 左列是一张深青绿的主任务卡“分析经营数据”，带醒目的趋势图形、交付说明“趋势、异常与增长机会”和一个小型箭头动作；它仍是 button，点击只预填现有 prompt。
- 右列垂直放置三张次级任务卡：制作汇报材料、整理客户洞察、调研市场机会。它们采用短横向布局，带序号、小图标、任务名称与交付结果；每张卡的悬停效果独立且克制。
- 区块标题的右侧辅助说明改为更轻的键盘提示或“选择后可继续编辑”，不再与标题等权。
- 现有“从问题到交付”能力带变成紧凑的胶囊标签行，与卡片区形成视觉收尾。

移动端回退为一张主卡加三张纵向次级卡，保持阅读顺序和完整点击目标。

## 实现边界

- 只编辑 `framework/client/task-workbench.tsx` 的新任务空态，复用已有 `prompt`、`setPrompt`、`setResearchMode` 和 `Icon`。
- 不新增接口、数据请求、外部图片或动画资产。
- 四个任务的名称、预填 prompt、`research` 取值不变。
- 不修改任务详情页、文件上传、提交按钮或键盘行为。

## 交互与可访问性

- 每张任务卡仍是原生 `<button type="button">`，具备键盘焦点和当前全局 focus-visible 样式。
- 主卡的深色背景必须保证文字、图标与 hover 态的对比度；装饰图形应 `aria-hidden`。
- 点击任意入口只能预填，不能自动发送或抢占 textarea 焦点。
- 窄屏不产生横向滚动，次级卡的文字允许截断前换行。

## 验证

1. `pnpm typecheck` 通过。
2. `pnpm lint` 无新增错误。
3. 桌面与 390px 宽视口下检查入口区没有溢出、主次层级清晰。
4. 逐项点击四张任务卡，确认 prompt 和研究模式与改造前一致。
