# Quill 业务工作台首页设计

**状态：已确认设计方向，待实现**  
**日期：2026-09-02**

## 目标

将 Quill `/quill` 的新任务空态从“居中聊天表单”重构为面向泛知识工作与业务任务的启动工作台。它应让首次到访者在几秒内理解：可以把一项业务目标、资料或问题交给 Quill，并得到可复核、可交付的结果。

成功标准：首屏不再显得像未完成的默认聊天界面；核心发起任务路径仍为一个可编辑的自然语言简报；现有文件上传、研究模式、快捷任务和任务创建行为保持不变。

## 选定视觉方向

采用“聚焦型工作台”：暖白背景、墨黑文字、深青绿单点强调色；衬线大标题承担可信度，无衬线正文保证效率。避免技术控制台、霓虹色、虚假的实时状态及过度装饰。

页面的叙事顺序为：

1. 轻量工作区上下文（Quill / 新任务）。
2. 面向业务结果的价值主张。
3. 任务简报输入器，带资料、模式与提交动作。
4. 四个真实的业务起点。
5. 低调的交付保障，说明研究、制作、核查和导出能力。

## 页面与组件

只调整 `framework/client/task-workbench.tsx` 中 `!sessionId && !taskId` 的新任务分支；不改变任务详情、路由、接口或持久化模型。

### `BusinessHero`

用纯展示组件替换现有大留白 `PageHeader` 组合。包含眼眉“QUILL · 业务工作台”、标题“把一个业务目标，变成可交付的成果。”以及一句结果导向的说明。标题中的“可交付的成果”使用现有 accent token。移动端保持左对齐；桌面端使用不超过 760px 的阅读宽度。

### `TaskBriefComposer`

保留同一个受控 `prompt`、`send()`、文件选择、`researchMode` 和键盘行为，但改变容器语义和布局：

- 顶部标签为“描述你希望达成的结果”；正文输入区不再用四行空白撑高，改为一段说明、输入框和上下文工具栏。
- 输入 placeholder 改为业务语言，例如“分析这份经营数据，找出增长机会并制作一页管理层汇报”。
- 文件按钮文案改为“添加资料”；模式按钮显示“研究模式”或“执行任务”。
- 提交按钮显示“开始处理”，小屏可只保留上箭头图标；禁用规则完全沿用当前实现。
- 提示 `⌘/Ctrl + Enter` 仅作为辅助信息，不与主动作竞争。

### `BusinessStarterGrid`

替换目前包含“检查代码问题”的通用卡片。四项快捷任务均沿用“点击仅预填 prompt，不自动提交”的现有交互：

| 名称 | 预填任务 | 模式 |
| --- | --- | --- |
| 分析经营数据 | 分析上传的经营数据，找出关键趋势、异常和增长机会，并给出优先行动建议。 | 执行任务 |
| 制作汇报材料 | 根据现有资料，整理为一份包含结论、数据依据和行动建议的管理层汇报。 | 执行任务 |
| 整理客户洞察 | 阅读客户反馈、访谈或工单资料，归纳客户需求、问题与优先级，并形成洞察摘要。 | 执行任务 |
| 调研市场机会 | 调研目标行业、竞品和用户需求，给出有来源依据的市场机会与建议。 | 研究模式 |

卡片使用小型线性图标、标签和一行交付预期；它们应更短、更紧凑，桌面端四列、窄屏两列。

### `DeliveryAssurance`

位于快捷任务下方的纯展示行：`研究与分析 / 文档与汇报 / 数据与图表 / 可下载交付`。它只建立产品能力认知，不能伪造“运行中”“在线 Agent 数量”等实时数据。

## 交互与状态

- 空 prompt、发送中、文件上传中或工作区未加载时，提交按钮禁用，逻辑不变。
- 在一个快捷任务被点击后，相应 prompt 和研究模式立即更新；焦点可留在卡片，用户可继续编辑简报再发送。
- 文件附件沿用 `FileAttachments`，达到十个文件上限时沿用当前截断行为。
- 若工作区加载失败，继续显示现有“无法加载工作区”，且保持不可提交；不为视觉刷新掩盖该错误。
- 登录门禁、进入任务详情以及后续会话视图完全不变。

## 可访问性与响应式

- 保持真实 `<form>`、`<textarea>` 和 `<button>`；快捷任务仍为可聚焦 button。
- 新增的展示性标志不得替代文字标签；强调色与背景须沿用主题 token 以保证对比度。
- `sm` 以下首屏纵向排列，输入器工具栏可换行；快捷卡片保持两列，极窄视口退回单列。
- 不为图片或装饰球引入必须下载的资产，确保首屏稳定、轻量。

## 验证

1. `pnpm typecheck` 通过。
2. `pnpm lint` 通过。
3. 在桌面和约 390px 宽视口检查：标题、任务简报、工具栏、快捷任务没有溢出，首屏焦点明确。
4. 手工验证：普通任务、研究任务、文件添加、空输入禁用、Enter/Shift+Enter 行为以及任一快捷任务预填。
5. 确认 `/quill/t/:taskId` 等任务详情路径视觉与行为未发生变化。

## 非目标

- 不新增后端接口、模板系统、最近任务数据或个性化推荐。
- 不修改全局 theme token 或其它产品页面。
- 不改变 Agent 规划、执行或产物交付能力。
